General

What exactly is Token Trail?

Token Trail is a free, open-source desktop dashboard for the Linux desktop that helps you understand your local OpenAI Codex usage. It shows quota windows with used and remaining percentages, token activity over time, reset times with countdowns, credits and spending limits, and related metrics, all in one place.

It is strictly read-only: it observes account-level data reported by your own Codex CLI installation and presents it clearly. It cannot start tasks, change your account, or redeem credits.

Is it really free? What is the license?

Yes. Token Trail is licensed under GPL-3.0-only, and the complete source code is public at github.com/amanalip/tokentrail. There is no paid tier, no account to create, and no subscription.

Which platforms are supported?

Linux desktop environments, for x64 (amd64) and arm64 (aarch64) machines. Packages ship as AppImage, deb (Debian, Ubuntu, Mint), rpm (Fedora, openSUSE), and Pacman (Arch, CachyOS, Manjaro). Verified configurations are listed in the compatibility and support matrix; untested environments may still work.

What is the project's status?

The complete v1 read-only product scope is implemented and machine-verified across development versions 0.1.0 through 0.5.x, with screenshot-backed test reports recorded per version. The project is currently moving through packaging, release automation, and release validation. Artifacts are unsigned development previews until an approved signing plan exists.

Do I need a Codex account or subscription?

You need a working OpenAI Codex CLI installation signed in to a Codex plan. Token Trail itself requires no account: it starts its own local Codex app-server process and reads only what Codex reports for your existing session.

Privacy and security

Can Token Trail read my prompts or Codex conversations?

No, as an enforced boundary rather than a policy. Token Trail reads exactly three kinds of data from Codex (account information, rate-limit windows, and aggregate token usage) plus one rate-limit update notification, through an allowlist checked before anything reaches Codex. The only other protocol traffic is the standard handshake required to start the app-server session. Prompts, responses, tasks, repositories, files, tool calls, agent transcripts, and browser sessions are structurally outside what the application can request or store, and responses are validated then stripped of every field outside the approved set.

Privacy guide

Where is my usage data stored?

Nowhere, in practice. Usage snapshots, quota values, and session deltas live only in RAM while Token Trail runs; closing the app erases them completely. The only file ever written to disk is your preferences document at ~/.config/Token Trail/, which holds display choices like theme and refresh settings. No usage value, timestamp, or account detail can appear in it.

Does Token Trail have telemetry or make network connections?

No. No telemetry, no crash reporting, no analytics, no update checks, no remote fonts or assets. The packaged build's Content Security Policy blocks remote script and style sources outright. All network activity belonging to your Codex usage happens inside Codex's own processes under its own privacy terms.

Does Token Trail handle my login or API keys?

Never. Authentication belongs entirely to Codex. If you are signed out, Token Trail shows a signed-out state and you fix it by running codex login yourself. Credentials never pass through or rest inside Token Trail, so there is nothing stored to leak and nothing to re-enter inside the app.

Can it change my account or spend my credits?

No. Token Trail has no write access of any kind: no task control, no credit redemption, no account changes. The read-only boundary is enforced in code, not by a setting you could loosen.

What is inside the diagnostics export? Is it safe to share?

The support document built in Settings & Diagnostics comes from a fixed, closed schema: application/Electron/Chromium/Node versions, platform and session details, theme, connection facts such as the refresh category, and coarse sanitized health, coverage, and session counters. Email addresses, identifiers, file paths, prompts, responses, raw protocol messages, and unknown fields are structurally excluded, and automated tests plant canary values for every sensitive class to prove they cannot leak. You preview the complete export before choosing where to save it, which makes it designed to be safe to attach when asking for help.

Installation

Why are downloads called unsigned development previews?

Packages are not code-signed yet because an approved signing plan is still pending. That means your OS may show unknown-publisher warnings. To be safe, always verify checksums before running anything:

sha256sum -c SHA256SUMS.txt --ignore-missing

Every downloaded file must print OK. A mismatch means the file is not the reviewed build; do not run it.

The AppImage will not start. What do I do?

Classic AppImages need FUSE 2 on most distributions:

sudo apt install libfuse2

On Fedora use sudo dnf install fuse; on Arch family use sudo pacman -S --needed fuse2. As a fallback you can skip FUSE entirely by extracting and running in place:

./tokentrail-*-linux-x86_64.AppImage --appimage-extract-and-run

Troubleshooting guide

Are "Source code" links on the release page installable?

No. The automatic zip and tar.gz snapshots contain repository text only, not a runnable build, and they are absent from SHA256SUMS.txt. Install only the tokentrail-* artifacts matching your architecture, such as tokentrail-0.5.0-linux-amd64.deb.

How do I uninstall Token Trail?

Per format: delete the AppImage file, or remove the native package with your package manager (sudo apt remove tokentrail, sudo dnf remove, or sudo pacman -R). Removing the package removes exactly its own files. To also erase preferences, clear data from Settings & Diagnostics or delete ~/.config/Token Trail/. There is nothing else to clean up because there is nothing else on disk.

Reading the numbers

What do the provenance labels on each value mean?

Every metric carries its origin with it:

  • Codex-reported: read directly from Codex.
  • Locally observed: measured locally by Token Trail, such as when a value was last refreshed.
  • Calculated by Token Trail: derived from reported source ranges.
  • Unavailable: not present, invalid, or unsupported by your Codex version, shown with a reason instead of an invented number.

Summaries over incomplete date ranges are additionally flagged as covering only part of the period you asked about. This labeling exists so honest numbers and honest gaps look different at a glance.

Why does something show Unavailable instead of zero?

Because an empty-looking value can mean three distinct things, and Token Trail deliberately distinguishes them: reported zero (Codex said zero), missing (Codex did not include the field), and unavailable with a reason (invalid, unsupported, or failed input). None is ever silently converted to zero. If your installed Codex version lacks support for an approved read, upgrading the CLI usually restores the missing values while everything else keeps working.

Do token totals and quota percentages add up to each other?

No, and that is intentional. They measure different things reported by different mechanisms, so Token Trail displays both without blending them into one number. The Learn route inside the app explains the relationship in depth, linked contextually from the metrics themselves.

Why is my history gone after closing the app?

By design. v1 keeps everything in memory only, with no history file, cache, or sync target, so nothing about your usage survives closing the window. Session-to-session observations within one run are also memory-only. This is the privacy tradeoff made deliberately: maximum honesty about current state, zero data retention.

Does it refresh automatically?

Token Trail runs no polling timers of its own. Data is read at startup, whenever you press the refresh control, and when Codex itself pushes a rate-limit update notification, which triggers a fresh approved read so quota changes appear without a click.

An automatic-refresh option exists in Settings but stays off by default and is not yet wired to any scheduler; the app labels this honestly as pending evidence.

Troubleshooting

Token Trail says the Codex CLI is unavailable, but codex works in my terminal.

This almost always means your desktop session's PATH differs from your shell's PATH. Menu launches do not read .bashrc. Confirm the CLI resolves in a terminal first:

which codex && codex --version

If that works but the app still cannot find it, link the directory containing codex into a standard location such as /usr/local/bin, then press refresh.

It shows a signed-out state, but I am logged in.

Codex itself has no authenticated session visible to Token Trail. Fix it through Codex directly:

codex login

Then refresh. Token Trail never asks for credentials itself.

Where do I get help?

Export the redacted diagnostics document from Settings & Diagnostics (it is designed to be safe to share), then open an issue at github.com/amanalip/tokentrail/issues with the file attached. The troubleshooting and known-limitations guides cover most other cases.
