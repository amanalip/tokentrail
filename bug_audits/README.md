# Bug audits

Keep dated bug audit documents and their fix progress in this directory.

Use descriptive, dated filenames such as `bugs_sept7.md`. Include the year when needed to distinguish audits across years. Each audit should record its repository baseline, findings, verification evidence, fix progress, and remaining work.

## Keeping fix status current

For each audit, maintain one status-table row per bug. Include the bug ID, priority, finding, current status, fix commit(s), and verification evidence or remaining work.

Update the table in the same batch as each fix. Mark a bug Fixed only after the fix is committed and relevant verification passes. Use In progress for unfinished work and Reopened when a previously fixed issue returns. Keep the table totals, reconciliation date, progress notes, and remaining-work list aligned, and preserve the original findings as historical evidence.

Follow each audit's release requirements. For the September 7 audit, all bugs must be fixed and verified, and the website must be checked and updated to match the application before creating a release.
